#### Requirement

Define the plain data types and error types every other module shares (design D2, D3, D7). No `fastmcp` or `mcp` imports.

- `src/any_mcp/types.py`: frozen dataclasses `HttpBinding`, `ToolSpec`, `ToolCall`, `RawResponse`, `ToolResult` with the fields in Interfaces.
- `ToolSpec` validation in `__post_init__`: non-empty `name` and `description`; at most one of `input_schema` and `input_model`; at most one of `http` and `handler`. `ToolSpec.json_schema()` returns a dict: the `input_schema`, the pydantic `input_model.model_json_schema()`, or `{"type": "object", "additionalProperties": false}` for a no-argument tool.
- `RawResponse.json()` parses the body (or returns `value` when the response wraps a handler value), `RawResponse.text()` decodes with the content-type charset (default utf-8, replacement on errors), `RawResponse.from_value(value)` wraps a handler return: `str` gives `text/plain`, `bytes` gives `application/octet-stream`, any JSON-serialisable value gives `application/json`, status 200.
- `src/any_mcp/errors.py`: `AnyMcpError`, `Deny`, `ToolInputError(errors: list[tuple[str, str]])` (JSON path, message), `UpstreamError(response: RawResponse)`, `ConfigError`, `UnknownTool`, and `error_result(exc, *, plugin, expose_details=False) -> ToolResult`.
- `error_result` returns `is_error=True`, a one-line text, and `structured={"error": {"kind": ..., "message": ..., "status": ...}}` (`status` only for upstream). Kinds: `Deny` gives `denied` with its message; `ToolInputError` gives `invalid_arguments` listing every path and message; `UpstreamError` gives `upstream` with the status and at most 500 characters of body text; `TimeoutError` and `asyncio.TimeoutError` give `timeout`; anything else gives `internal` with `<plugin> failed: <ExceptionType>`, plus the message only when `expose_details` is true. No header value ever appears in the text.

### S4: Config model

- Status: done

#### Requirement

Define the any-mcp YAML config file and its loader (design D5). This is the `any-mcp-config` contract the agent-orchestrator epic renders into a ConfigMap.

- Pydantic models, all `extra="forbid"`: `AnyMcpConfig(server, tools, python_path, plugins)`, `ServerSettings(name="any-mcp", instructions=None, transport="stdio" | "http", log_level="info", http)`, `HttpSettings(host="127.0.0.1", port=8000, path="/mcp", bearer_token=None, allowed_origins=[])`, `ToolSettings(max_name_length=60 (16 to 128), list_ttl_ms=30000, cache_scope="public" | "private", response_budget_chars=40000)`, `PluginEntry(name, plugin, namespace=None, allow=[], tags=[], timeout=None, reload_every=None, config={})`.
- `PluginEntry.name` matches `^[a-z][a-z0-9_-]{0,19}$`; two entries with the same name are rejected.
- `load_config(path, *, env=None) -> AnyMcpConfig`: reads YAML; expands `${VAR}` and `${VAR:-default}` in every string value, nested ones included, from `env` (default `os.environ`); a missing variable with no default raises `ConfigError` naming the variable and the key path; records the config file's directory as `base_dir` and resolves `python_path` entries against it.
- `config_from_plugins(refs) -> AnyMcpConfig`: one entry per `--plugin` reference with defaults; the entry name is the lowercased class name for `module:Class` and the reference itself for an entry-point name.
- The file may be YAML or JSON (JSON is valid YAML; parse with `yaml.safe_load`, which reads both): the agent-orchestrator onStart script has only the standard library and writes `any-mcp.yaml` with `json.dumps` (design D20). A path ending `.json` is read the same way.
- Every failure (unreadable file, YAML error, a non-mapping top level, an unknown key, a validation error) raises `ConfigError` whose message names the file and the dotted key path.

#### Requirement

Execute a declarative `HttpBinding` with httpx so a plugin can describe an endpoint and write no call code (design D3, D11).

- `make_client(base_url, *, transport=None, timeout=30.0) -> httpx.AsyncClient`: `User-Agent: any-mcp/<version>`, no `Authorization` or `Cookie` header, the given transport when not `None` (tests pass `httpx.MockTransport`).

- Status `>= 400` raises `UpstreamError` carrying the `RawResponse`; any other status returns `RawResponse(status, headers, body, content_type)`.
- Nothing from an inbound MCP request is an input here: only the `ToolCall` arguments and the `headers` parameter reach the request.

#### Requirement

Turn a `RawResponse` into a `ToolResult` with the default shaping rules and a size budget (design D9).

- `shape_default(raw, *, budget_chars=40000, output_schema=None) -> ToolResult`.
- JSON (`application/json`, any `+json` type, or a handler value wrapped by `RawResponse.from_value`): `structured` is the parsed value and `text` is its compact JSON dump (`ensure_ascii=False`, separators `(",", ":")`). A handler `str` value is plain text with no structured content.
- `text/*`: text only, decoded with `RawResponse.text()`.
- Other content types: text `<n> bytes of <content type>`, no structured content.
- Empty body: text `OK (<status>)`.
- Over `budget_chars`: text cut to the budget plus `\n[truncated: <shown> of <total> chars]`, structured dropped; when `output_schema` is given the result is instead `is_error=True` with a text naming the response size and the budget, because structured content must conform to the output schema.

### S7: Schemas and validation

- Status: done

#### Requirement

Normalise tool schemas and names for listing, and validate call arguments against the original schema (design D6, D7).

- `normalize_schema(schema, *, max_depth=8) -> dict`: inline local `$ref`s (`#/$defs/...`, `#/definitions/...`, `#/components/schemas/...`, given a root document to resolve against), drop `$defs` and `definitions` afterwards, replace a reference recursing deeper than `max_depth` with `{"type": "object", "description": "(recursive, truncated)"}`; an external or unresolvable `$ref` raises `SchemaError` naming the ref.
- `listing_schema(schema) -> dict`: a root `anyOf`/`oneOf` whose branches are all object schemas becomes one object schema (properties merged, `required` the intersection); a root without `type: object` otherwise raises `SchemaError`; `None` gives `{"type": "object", "additionalProperties": false}`.
- `exposed_name(namespace, tool, *, max_length=60) -> str`: `<namespace>_<tool>` (no prefix when the namespace is empty), every character outside `[A-Za-z0-9_.-]` replaced by `_`, and a name longer than `max_length` cut and suffixed with `_` plus the first 6 hex digits of the SHA-1 of the untruncated name, so the result is deterministic and at most `max_length` long.
- `SchemaError` subclasses `ConfigError`.
- `validate_arguments(schema, arguments) -> dict`: `None` means `{}`; validation with `jsonschema.Draft202012Validator`; every error is collected and raised as one `ToolInputError` with `(json path, message)` pairs sorted by path; a string value whose schema expects an object or array and that parses as JSON of that type is replaced by the parsed value before validation; returns the (possibly coerced) arguments.

- AC1: local refs under $defs, definitions and components/schemas are inlined and the definition maps are removed [evidence: test:tests/test_schema.py::test_inlines_local_refs]
- AC2: recursive refs are cut at max_depth with the truncation marker schema [evidence: test:tests/test_schema.py::test_cuts_recursive_refs]
- AC3: an external or unresolvable ref raises SchemaError naming it [evidence: test:tests/test_schema.py::test_rejects_external_refs]

#### Requirement

Aggregate loaded plugins into one global, deterministic tool list with lifecycle and reload (design D6, D8).

- `ToolRegistry(plugins, settings)`. `start()`: for each plugin in order, `setup()` then the first `load_tools()`; a failure raises `ConfigError` naming the plugin (plugins already set up are torn down first). `stop()`: cancels periodic reloads and runs `teardown()` for every plugin that was set up, in reverse order, continuing past failures (each logged).

- `run_periodic()`: for each plugin with `reload_every`, reloads that plugin every `reload_every` seconds until `stop()`.
