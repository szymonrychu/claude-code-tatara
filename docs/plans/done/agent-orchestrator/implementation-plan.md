### S10: dispatch queue sql

- Status: done
- Files: `src/agent_orchestrator/db/queue.py`, `tests/test_dispatch_queue.py`
- Verify: `uv run pytest tests/test_dispatch_queue.py -q && mise run lint`

#### Requirement

The SQL of the three queue tables, `messages`, `commands` and `checks` (D2, D4, D23, D24). Every status change is a guarded UPDATE (`WHERE status = <expected>`), and a function reports whether it won.

Messages:
- `enqueue_message(conn, cluster_id, text, target_agent_id=None) -> id` and NOTIFY `message_queued {cluster_id}`
- `cancel_message(conn, id) -> bool` (only from queued)
- `retry_message(conn, id) -> bool` (only from failed; resets attempts, error, not_before and ambiguous_at; the user's explicit Retry)
- `claim_and_pick(conn) -> Claim | None`: one transaction, one clock. Every comparison and write uses Postgres `now()`; wrapper timestamps are stored but never compared with database time (D23).
  - Candidates are the oldest queued message of each cluster. For each, in id order, take `pg_try_advisory_xact_lock` on a per-cluster key and skip the cluster when another dispatcher holds it, so two dispatchers can never take msg2 before msg1 (FIFO per cluster).
  - Under the lock, read the cluster's oldest queued message that can be dispatched now: `not_before` null or not after `now()`, and an untargeted message or a targeted one whose target is pickable. An untargeted head message still waiting out its backoff (`not_before > now()`) holds its cluster: no later message of that cluster is claimed before it (FIFO, D4). A targeted message whose target is busy or booting is skipped (it does not block later messages); a targeted message whose target has `gone_at` set (or no longer exists) is marked `failed` with error `target_gone` and the scan continues (D23).
  - Claim it with `FOR UPDATE SKIP LOCKED`. Pick the agent of that cluster that is `ready`, has `gone_at IS NULL` and a session, has state idle, matches `target_agent_id` when set, and has `free_since` newer than `agents.last_dispatched_at` (the reservation rule; null last_dispatched_at counts as older). Order by `free_since ASC`, `FOR UPDATE OF agents SKIP LOCKED`, limit 1.
  - On a pick, in the same transaction, UPDATE the agent row setting `last_dispatched_at = now()` (the row change makes a concurrent READ COMMITTED claim recheck the predicate instead of using a stale snapshot) and mark the message `dispatching` with agent_id, `dispatched_at = now()` and `heartbeat_at = now()`. Return the Claim, which carries the agent's previous `last_dispatched_at`.
  - With no free agent, leave the message queued and try the next cluster, so one busy cluster never blocks another.
- `release_agent(conn, agent_id, previous_dispatched_at)`: restores `last_dispatched_at` after any outcome where no turn was accepted (409, unavailable, gone, config error, rejected, a requeue), so the agent is pickable again on the next pass (D23). Never called for an accepted or ambiguous send.
- `heartbeat_dispatching(conn, id) -> bool`: sets `heartbeat_at = now()` while the row is still `dispatching` (D24).
- `fail_message(conn, id, error) -> bool`: guarded `dispatching` to `failed` with a reason, no retry (the permanent outcomes `rejected` and `config_error`, D24).
- `mark_sent(conn, id, turn_id)`; `requeue(conn, id)` (409: back to queued, attempts unchanged, no backoff).
- `record_failure(conn, id, error, max_attempts, backoff_base, backoff_max) -> str`: a definite non-accept (unavailable, session_gone). It increments `attempts`. Below max_attempts the message goes back to queued with `not_before = now() + least(backoff_base * 2^(attempts - 1), backoff_max)` seconds, counting the new attempts. At max_attempts it becomes `failed` with the error. It returns the new status.
- Ambiguous outcomes (D24). Each is guarded, and the reservation is kept unless stated otherwise:
  - `mark_verifying(conn, id, reason) -> bool`: `dispatching` to `verifying`, with `ambiguous_at = now()` and error `reason` (`ambiguous` or `dispatcher_lost`).
  - `list_verifying(conn, limit) -> list[Verifying]`: the message, its agent's url, session_id and cluster_id, its `dispatched_at`, and `age_seconds = extract(epoch from now() - ambiguous_at)` from the database clock.
  - `resolve_started(conn, id, turn_id) -> bool`: `verifying` to `sent`.
  - `resolve_not_started(conn, id, max_attempts, backoff_base, backoff_max) -> str`: `verifying` back to queued with backoff, or `failed` with `ambiguous_not_started` at max, with the attempt counted. In the same transaction it clears the reservation only while it is still this message's: `UPDATE agents SET last_dispatched_at = NULL WHERE id = <agent> AND last_dispatched_at = <message.dispatched_at>`.
  - `fail_ambiguous(conn, id) -> bool`: `verifying` to `failed` with error `ambiguous`.
- `verify_stale_dispatching(conn, older_than_seconds) -> int`: dispatching rows whose `coalesce(heartbeat_at, dispatched_at)` is older than the bound (database clock) move to `verifying` with error `dispatcher_lost`. They are never re-sent blindly, because the turn may already have been accepted; the verifier decides (D24).
- Every transition NOTIFYs `status {cluster_id}`.

Commands:
- `enqueue_command(conn, agent_id, kind) -> id`
- `claim_command(conn, kinds) -> Command | None` (SKIP LOCKED, sets running)
- `complete_command(conn, id, status, result)`

#### Requirement

The dispatcher (D4, D23, D24).

`Dispatcher.run(stop)` wakes on NOTIFY `agent_free` or `message_queued`, and also every `settings.dispatch_poll_seconds`.

Each wake drains:
- Loop `claim_and_pick` until it returns None.
- For each claim, POST the turn to the picked agent's URL and session with the cluster's derived auth token and `metadata {orch_message_id: <id>, orch_attempt: <attempts + 1>}` (the verifier matches on it, D24), up to 8 sends in flight, with `settings.wrapper_send_timeout_seconds` as the send timeout. While a send is in flight the dispatching row heartbeats every `settings.dispatching_heartbeat_seconds` (`heartbeat_dispatching`) (D24). Result mapping (D23, D24, D27):
  - TurnAccepted: `mark_sent` with turn_id. The reservation stays (the free_since rule covers it).
  - Busy: `release_agent`, then `requeue`.
  - Unavailable (5xx, connect errors): `release_agent`, then `record_failure` with the cluster's `spec.max_attempts`, error `unavailable` and the settings backoff: automatic retry after `not_before`.
  - Gone (404, 410): `release_agent`, `record_failure` with error `session_gone` and the settings backoff, and `enqueue_command(agent_id, 'rebootstrap')` so the reconciler clears the agent's session and bootstraps again.
  - ConfigError (401, 403): `release_agent`, `fail_message` with `config_error`; permanent, no retry.
  - Rejected (413, 422): `release_agent`, `fail_message` with `rejected`; permanent, no retry.
  - Ambiguous (timeout or reset after the request was written): `mark_verifying` with reason `ambiguous`. It is never re-sent here; the reservation is kept because the turn may be running, and the verifier (task ambiguous-send-verifier) decides.
- Claim `interrupt` and `compact` commands and call `interrupt` or `command(compact)`. Complete each as done with the wrapper response, or as failed with the error.
- Call `verify_stale_dispatching(settings.dispatching_stale_seconds)`.
- Call the verifier hook `self.verify_pending()`; this task makes it a no-op that ambiguous-send-verifier replaces.

A crash between claim commit and send leaves a dispatching row. The stale rule hands it to the verifier rather than re-sending it.

#### Requirement

`Ingester.run(stop)` keeps one task per agent that has a session and no `gone_at`. It refreshes that set every `settings.ingest_refresh_seconds`, starts a task for each new agent and cancels the task of each removed one.

Per agent:
- On attach, GET the snapshot and upsert `agent_status`.
  - State mapping: ready becomes idle, busy stays busy, creating becomes booting, and stopped, failed or dead become dead.
  - `free_since` is the database `now()` at the moment the ingester records a transition into idle (D23: one clock; wrapper timestamps are never compared with database time). The wrapper `idle_since` is stored in `agent_status.wrapper_idle_since` for display only. An attach whose snapshot is idle while the stored state was not idle counts as such a transition.

- Also on attach, GET `/v1/peers` into `agent_status.peers` (the member list as returned: `enabled`, `self`, `members[{instance, url, sessions, last_seen_at, missed}]`) and set the peer count to `len(members)`, 0 when `enabled` is false. Refresh it on every `session_state` transition into idle.
- Then stream events with `Last-Event-ID = last_seq` of that session.

Per envelope:
- Store it with `insert_events`. A seq greater than last_seq+1 first writes `insert_gap`.
- `session_state`: set state. A transition into idle (stored state was not idle) sets `free_since = now()` (database clock), stores `data.since` in `wrapper_idle_since`, and NOTIFYs `agent_free {cluster_id, agent_id}`. Every state change NOTIFYs `status {cluster_id}`.
- `context`: set the context columns, then NOTIFY `status`.
- `user_message`: stored as an `events` row like every other type and rendered by the chat as a user chat row, or a peer chat row when `origin` is `peer`. It uses the wrapper origin vocabulary `client|initial|agent|peer|restart|command` (turns.py:27 plus `restart` and `command`; `command` has `turn_id` null); `restart` rows are rendered as a system continue line. The ingester does not project it into `turns`.
- `turn_started`, `turn_completed`, `turn_failed`: upsert `turns` (origin, started_at, completed_at, status, final_text, usage).
- `session_closed`: state dead; the stream stops until the reconciler records a new session.
- Update `last_seq` and `updated_at`.

On disconnect, reconnect with backoff from 1 s doubling to 30 s, reset by a received event.

`db/status.py` (ingester is the writer): `upsert_status`, `set_state`, `set_context`, `set_peers`, `upsert_turn`.

#### Requirement

The ambiguous-send verifier (D24). Before any automatic retry, it checks with the wrapper whether a turn whose outcome was ambiguous actually started, so a message is never pasted into a session twice.

`dispatcher/verify.py`: `Verifier(pool, settings, wrapper_factory)`. Its `verify_once()` handles at most 50 messages per pass, from `list_verifying` (task dispatch-queue-sql). For each message it builds a `WrapperClient` for the message's original agent, with the cluster's derived token, and decides:

- Started. The wrapper snapshot has `current_turn_id` and that turn record's `metadata.orch_message_id` equals the message id, or one of the newest 10 turns of `list_turns` has a record carrying it. Then `resolve_started(id, turn_id)`. The reservation stays.
- Definitely not started. The wrapper answered the snapshot and the turn lookups, no record carries the id, and `age_seconds >= settings.ambiguous_settle_seconds`. Then `resolve_not_started` with the cluster's `spec.max_attempts` and the settings backoff. This clears the reservation only while it is still this message's. The message is then retried automatically after its backoff, through the normal claim, possibly by another agent.
- Unknown. The wrapper is unreachable (`WrapperUnreachable`), the session answers 404, or the message is still inside the settle window. Then nothing changes and the message is checked again on the next pass.
- Deadline. `age_seconds >= settings.ambiguous_deadline_seconds` without a definite answer. Then `fail_ambiguous(id)`: failed with `ambiguous`. Only the user's explicit Retry re-sends it.

Database rules: every write is one of the guarded queue functions, so two dispatcher replicas verifying the same message never both resolve it. Time comparisons use only `age_seconds` from the database clock (D23).

Wiring in `dispatcher/loop.py`: `Dispatcher.verify_pending()` delegates to `Verifier.verify_once()`, so every drain pass runs it, once per wake and poll.

README.md gains `## Delivery and retries`. It covers:
- the outcome table: accepted, busy, unavailable, gone, config error, rejected and ambiguous
- the backoff formula and its settings
- the verifying state
- the settle window and deadline
- the never-twice rule, and the residual case of a turn the wrapper holds for longer than the settle window
